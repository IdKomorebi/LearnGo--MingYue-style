# 以 KaTrain 为底座，加入"理解 KataGo"的明玥式讲解：方案

> 一句话：KaTrain 已经把 KataGo 接好了，缺的是"理解层"。我们在它的数据层和界面层之间插入一个讲解层：先用确定性代码把 KataGo 的数字翻译成"发生了什么"（事实），再按明玥谈棋的讲法把事实说成人话（模板兜底 + LLM 润色），最后在面板和棋盘上呈现出来。

讲解层代码在 `katrain/core/explain/`，已用 KataGo 对 2016 年人机大战第四局 78 手（"神之一手"）前后的真实分析跑通，结果见第 7 节。

---

## 1. KaTrain 现在是怎么工作的（读 sanderland/katrain 主分支源码得出，v1.20.0）

| 层 | 文件 | 做什么 | 和讲解层的关系 |
|---|---|---|---|
| 引擎 | `katrain/core/engine.py` `KataGoEngine` | 启动 `katago analysis` 子进程，按行收发 JSON。`request_analysis()` 拼 query：`moves`、`includeOwnership`、`includeMovesOwnership`、`includePolicy`、`avoidMoves`（找替代手/限定区域）、`overrideSettings`（`reportAnalysisWinratesAs=BLACK`），pondering 用 `reportDuringSearchEvery` 流式返回 | 不用改。KataGo 内核已经在了；讲解层需要的数据（候选点、PV、ownership、policy）都已经请求了 |
| 远程引擎 | `katrain/core/remote_engine.py` | WebSocket 连远端 KataGo | 以后做 Web 版或手机端可以复用 |
| 数据 | `katrain/core/game_node.py` `GameNode` | `set_analysis()` 把结果存进 `node.analysis = {root, moves{gtp: moveInfo+order}, ownership, policy, completed}`；派生出 `candidate_moves`（带 `pointsLost`）、`points_lost`、`policy_ranking`；`comment()` 拼出现在信息面板里那几行英文/中文数字 | 讲解层的输入。`comment()` 就是 KaTrain 现在"讲解"的全部：只罗列数字，不解释 |
| AI 对手 | `katrain/core/ai.py` | 十几种 AI 策略，每种返回 `ai_thoughts` 字符串；`HumanStyleStrategy` 已经在用 KataGo 的 `humanSLProfile`（人类棋风模型，可按段位） | humanSL 可以直接拿来做"这手棋 5 级会下、业余 5 段不会下"这种明玥式段位梗 |
| 界面 | `katrain/gui/controlspanel.py` `update_evaluation()`、`badukpan.py`、`widgets/graph.py`、`gui.kv` | Kivy。信息面板显示 `comment()`；棋盘画候选点、ownership 阴影、PV；胜率/目差曲线 | 讲解文字先挂在信息面板；棋盘高亮复用 badukpan 现有画法 |
| 国际化 | `katrain/i18n/locales/cn` | 已有简体中文界面和字体 | 中文显示没有额外成本 |

结论：不需要"再接一个 KataGo 内核"，KaTrain 自带 KataGo（并内置 b10c384 transformer 模型），我们要做的是理解层。

## 2. 架构

```
KataGo analysis engine (JSON)            ← KaTrain 现有，不改
        │
GameNode.analysis（root/moves/ownership/policy）
        │  adapters.facts_from_game_node()
        ▼
① 事实层 facts.py（确定性，可单测）
   胜负手判定、目损/胜率损、实战 vs 推荐、PV 中文化、
   AI 第一感（policy）、局面复杂度、哪块棋死活变了、哪片地盘变了
        │  MoveFacts（JSON）
        ├────────────────────────┐
        ▼                        ▼
② 表达层·模板 style_mingyue.py   ② 表达层·LLM llm.py
   离线、即时、不会胡编             明玥口吻改写，只许用 facts 里的数据
   （兜底 + 给 LLM 当草稿）         后台线程生成，缓存在节点上
        └──────────┬─────────────┘
                   ▼
③ 呈现层：信息面板"讲解"段 → 后续：棋盘高亮（棋块/推荐点/PV 动画）、
   "为什么不下这里？"点选问答、整盘名场面列表、导出视频脚本
```

三条设计原则：

1. **事实和表达分开。** 所有"说什么"由代码从 KataGo 输出算出来，LLM 只决定"怎么说"。这样 LLM 不会讲出 KataGo 没算过的变化，讲错了也能定位是哪一层错。
2. **模板永远在。** 没网、没 key、LLM 拒答或超时时，模板版照样出讲解；LLM 版回来后替换显示。
3. **不动 KaTrain 的核心逻辑。** 讲解层是一个独立包 `katrain/core/explain/`，GUI 只加一个挂点，方便以后跟上游合并。

## 3. 事实层：把 KataGo 的每个输出变成"人能懂的事实"

| KataGo 输出 | 计算 | 翻译成的事实 | 讲解里怎么用 |
|---|---|---|---|
| `rootInfo.scoreLead`（落子前/后） | 落子方视角差值 | 这手亏了几目；按 KaTrain 阈值 12/6/3/1.5/0.5 分成 败着/恶手/疑问手/缓手/小亏/好棋 | "亏了 7 目，差不多一个贴目" |
| `rootInfo.winrate` | 前后对比 | 胜率涨跌、局势词（五五开/明显好下/大势已去） | AI 当裁判揭晓答案 |
| `moveInfos[].order/pv` | 实战在候选里的名次；最佳点 PV | 正解是哪、后续怎么走（中文位置 + 坐标） | "AI 想下的是右上角星位（Q16），后续……" |
| `policy` | 实战点的先验概率 | AI 第一感给这手多少；"好棋 + 第一感 < 5%" 记为妙手 | "AI 第一感只给 2%，是算出来的" |
| 候选点目差分布 | 与最佳差 1 目以内的个数 | 唯一的一手 / 哪里都行 | 区分"急所"和"大场随便选" |
| `ownership`（前/后） | 按棋块求平均归属，前后对比 | 哪块棋从"安定"变"危险"、从"未定"变"已死" | 屠龙、治孤、弃子的叙事主线 |
| `ownership`（前/后） | 按区域（四角、四边、中腹）累加差值 | 哪片地盘多了/少了几目 | "左下一带凭空多出 8 目" |
| `scoreStdev`、visits | 直接读 | 局面复杂度、AI 算得深不深 | 低 visits 时提醒"仅供参考" |
| （扩展）`humanSLProfile` 查询 | 同一局面按 5k / 1d / 5d / 职业 各问一次人类模型 | 各段位下这手的概率 | 明玥式段位梗："这手 5 级 40% 会下，业余 5 段只有 3%" |

## 4. 明玥风格怎么落成模板和提示词

旧 LearnGo 项目的会话在这个项目里读不到，下面是从明玥谈棋（B 站 / YouTube / 百家号，业余五段，"领悟围棋之美"）公开的视频标题和简介归纳的。**这是推断，不是从完整视频里总结的**；你手上如果有之前"学习明玥风格"的结论或几段字幕，给我后可以直接替换这一节。

| 风格要素 | 公开素材里的样子 | 模板实现 | 提示词实现 |
|---|---|---|---|
| 标题句冲击力 | "疯狂弃子，野蛮屠龙，百目对杀，诡异治孤！""中最毒飞刀，出最狗误算，放最鬼大招，磕最浪劫争！" | 按判定（妙手/好棋/缓手/恶手/败着）选四字对仗短语 | 要求开头一句四字短语、对仗、夸张 |
| 把棋手当角色 | "卞相壹见利忘命自投罗网，黄明宇奋不顾身强手绞杀" | 用棋手名开讲"他下在哪、想干什么" | 要求讲意图和心理，但推测要标"可能" |
| AI 当裁判、制造反转 | "AI 来了也得吐血""鹰之一手竟然暗藏神之一手？" | 先说实战，再亮胜率/目差变化 | 让 AI 揭晓答案，数字口语化 |
| 讲清棋理 | 死活题系列"劫活只能 2 级，净活才是 2 段" | 棋块死活变化、地盘变化、唯一手/哪里都行 | 要落到死活、厚薄、先后手、大小 |
| 段位梗收尾 | 同上 | 按判定选金句 | 结尾一句接地气金句 |
| 敢纠错 | "烂柯杯决胜局更正""纠正一个错误" | visits 低时加"仅供参考" | 同左 |

提示词全文见 `katrain/core/explain/llm.py` 的 `SYSTEM_PROMPT`，硬性规则是：只能用 `<facts>` 里的坐标和数字、不许自己推演变化、坐标给中文位置 + GTP 坐标、120~250 字。

想让风格更像，可以加一步：拿 5~10 段明玥视频字幕（你自己转写或提供），提炼成"句式库"和 2~3 个 few-shot 示例放进提示词。字幕只用作风格参考，不在产品里复述原文。

## 5. 模板还是 LLM？两者都要

| | 规则模板 | LLM（Claude） |
|---|---|---|
| 准确性 | 只说算出来的事实 | 受硬规则约束，仍需抽查 |
| 风格 | 句式有限，多看会重复 | 像真人讲解，能串故事 |
| 延迟/成本 | 0 | 每手一次 API 调用；只在用户停在某手时才调用并缓存 |
| 离线 | 可以 | 不行 |

默认：模板即时显示，LLM 开关打开后在后台生成、回来后替换。原型里的模型默认写的是 `claude-opus-5-5`、effort 设为 low（短文本改写够用），并开了服务端拒答回退（`fallbacks: "default"`）。觉得贵可以在配置里换成 Sonnet 或 Haiku，这一点由你决定。

## 6. 分阶段路线

**P0 原型（已完成）**
- `katrain/core/explain/`：事实层、明玥模板、LLM 提示词、KaTrain 适配器，带单元测试。
- 在 KaTrain 本地分支里接好：`katrain/core/explain/` + 信息面板"讲解"段 + `config.json` 的 `explain` 开关（`enabled` / `llm` / `model`），加了用真实 KataGo 数据跑的集成测试（KaTrain 自己算的目损和讲解层一致）；KaTrain 原有的棋盘/解析测试也一起跑过，13 个全过。

**P1 在 KaTrain 里真正好用**
- ✅ 独立的"讲解"标签页（和信息、详细、笔记并列，分析模式默认打开）。
- ✅ 棋盘联动：讲解打开时，AI 推荐点画青色圈，死活变差/变好的棋块画红/绿圈；讲解末尾有链接，点一下在棋盘上逐手播放 AI 推荐变化。
- ✅ 关键手（目损 ≥ 3 或妙手）自动把落子前后两个局面加算到 `explain/key_move_visits`（默认 1000），每手只加算一次。
- 设置界面里加讲解开关、LLM 模型和 API key（现在只能改 config.json）。

**P2 整盘理解**
- 拐点检测：扫胜率/目差曲线，挑出 3~5 个"名场面"，生成整盘复盘提纲（明玥视频本身就是这个结构）。
- 点选问答"为什么不下这里？"：用户点一个点，用 KaTrain 已有的 `refine_move` 让 KataGo 算这一手，再走事实层对比讲解。
- 多轮追问：在讲解面板里问"那如果白棋不应呢？"，用 KataGo 算新变化后再讲。

**P3 段位与内容生产**
- 接 humanSL 模型（KataGo `b18c384nbt-humanv0`，KaTrain 的 HumanStyleStrategy 已在用），讲"这手在你这个段位多少人会下"。
- 导出：整盘讲解导出为带注释的 SGF（KaTrain 已支持写 `C[]` 注释），或导出成视频口播稿和分镜。
- 语音朗读（TTS）。

## 7. 原型实测：人机大战第四局 77~79 手

环境：KataGo v1.18.1 Eigen（纯 CPU）+ KaTrain 自带的 b10c384h6nbttflrs 模型，每个局面 60 visits。CPU 很慢，所以 visits 偏低，数字只用来演示流程。

下面由 `demo.py` 原样生成：

```
============================================================
【第 77 手】滴水不漏，AI 点头。
AlphaGo（黑）这手下在左上角三路（F17）。
AI 怎么看？落子前黑方胜率 98%（基本锁定胜局），下完 98%（基本锁定胜局）。
朴素，但是正确，这就是高手。
（AI 这次只算了 61 步，判断比较浅，仅供参考。）
============================================================
【第 78 手】冷门妙手，AI 都没想到！
李世石（白）这手下在中腹（L11）。
AI 怎么看？落子前白方胜率 2%（几乎没机会了），下完 3%（几乎没机会了）。
最妙的是：AI 的第一感只给这手 3% 的概率，是靠算出来的，不是看出来的。
这种棋，第一感是看不到的，得算。会算的人，才配得上这一手。
（AI 这次只算了 61 步，判断比较浅，仅供参考。）
============================================================
【第 79 手】不是最佳，但也不算错。
AlphaGo（黑）这手下在中腹（K10）。
AI 怎么看？落子前黑方胜率 97%（基本锁定胜局），下完 95%（基本锁定胜局）。
AI 候选里排第 7。AI 想下的是中腹（J11），后续大致是：黑中腹(J11) → 白中腹(L12) → 黑中腹(M10) → 白左边5路(E8)。
对手的最佳应对：白中腹(J11) → 黑中腹(J10) → 白左边7路(G11) → 黑左边6路(F10)。
这点差别，业余比赛里根本不算事，但高手对局里，细节就是胜负。
（AI 这次只算了 61 步，判断比较浅，仅供参考。）
============================================================
【第 80 手】滴水不漏，AI 点头。
李世石（白）这手下在中腹（M10）。
AI 怎么看？落子前白方胜率 5%（几乎没机会了），下完 6%（大势已去）。
地盘上，上边一带多出了大约 4 目。
朴素，但是正确，这就是高手。
（AI 这次只算了 61 步，判断比较浅，仅供参考。）
```

几点观察：

- **第 78 手（李世石挖）被正确识别成"冷门妙手"**：AI 第一感只给 3%，但目数没亏。这正是"神之一手"该有的叙事。
- **第 79 手（AlphaGo 的 K10）**：AI 推荐 J11，实战排第 7，胜率 97% 掉到 95%。公认 79 手才是 AlphaGo 真正的失误，但 60 visits 的小网络只看出了一点点损失；visits 加上去以后，同一套事实层会自动把它升级成"恶手/败着"，讲法跟着变。这也说明 P1 里"关键手自动加 visits"是必须的。
- 低 visits 时，"唯一的一手 / 哪里都行"这类判断会自动不说，并在结尾提示"仅供参考"。

**在 KaTrain 界面里的样子**（`docs/mingyue/explain_panel_move78.png`、`explain_panel_move79.png`）：在无显示器的云环境里用 Xvfb 启动 KaTrain（中文界面），用回放录好的 KataGo 输出的假引擎（`tools/mingyue/replay_engine.py`）代替真引擎截图。右下是"讲解"标签页；第 79 手棋盘上 J11 的青色圈就是讲解里说的 AI 推荐点。

**怎么自己跑：**

```bash
# 1) 只跑讲解层（在仓库根目录）：
python tools/mingyue/demo.py tools/mingyue/g4_moves.json tests/data/g4_katago_analysis.jsonl --from 77 --to 80 --names AlphaGo 李世石
python tools/mingyue/demo.py ... --show-prompt   # 看发给 LLM 的完整提示词
python tools/mingyue/demo.py ... --llm           # 需要 pip install anthropic 和 ANTHROPIC_API_KEY

# 2) 跑 KaTrain：
uv run pytest tests/test_explain.py
uv run katrain                      # 设置里切到中文，打开任意棋谱、分析后即可在“详细”里看到讲解
# 想开 LLM 版：在 ~/.katrain/config.json 里加 "explain": {"enabled": true, "llm": true, "model": "claude-opus-5-5"}
```


## 8. 已知限制

- 让子棋的初始摆子（AB/AW）在适配器里还没处理，`board.py` 只回放 `moves`。KaTrain 侧要把 `node.placements` 一起放进去。
- 棋块死活用 ownership 均值判定，对劫争、双活、大块对杀的边界情况会粗糙，P1 需要加劫和气数信息。
- "区域"按九宫格切分，跨区大龙会被归到占比最大的那块。
- 模板句式数量少，连续看会重复；LLM 版解决这个问题。
- 界面只在 Xvfb 里用回放引擎截过图，没有在真实桌面和真实 KataGo 上交互使用过；讲解目前挤在信息面板里，面板小时要滚动。
- LLM 版的代码写好了，但这次没有调用 Claude API 实测（需要你的 API key，也会产生费用）。

## 9. 需要你决定的事

1. **代码放哪？** 已定：本仓库 main 分支，基于 KaTrain 完整历史（MIT 协议），上游更新可以随时合并。
2. **LLM 用哪个、要不要离线？** 默认 Claude（需要你的 API key），也可以先只用模板版。
3. **明玥风格素材。** 如果你有之前 LearnGo 里"学习明玥风格"的结论或字幕，发给我，我替换第 4 节并加 few-shot 示例。
